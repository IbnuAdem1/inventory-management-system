## 1. FULL ARCHITECTURE OVERVIEW

This is a **pure frontend Single Page Application (SPA)** built with React + Vite. There is no backend, no database, no API, and no authentication system. It is a UI prototype for an automotive spare parts management system called **AutoPartsPro**.

```
Browser
  └── React SPA (Vite)
        ├── React Router DOM (client-side routing)
        ├── Tailwind CSS + shadcn/ui (styling & components)
        ├── @tanstack/react-query (installed, NEVER used)
        ├── react-hook-form + zod (installed, NEVER used)
        └── All data: hardcoded const arrays inside each page file
```

There is no:
- Backend server (Node.js, Express, Fastify, etc.)
- Database (PostgreSQL, MySQL, SQLite, MongoDB, etc.)
- Authentication system (JWT, sessions, OAuth, etc.)
- API layer (REST or GraphQL)
- State management (Redux, Zustand, Context, etc.)
- Environment variables

---

## 4. CURRENT PROJECT WEAKNESSES

1. **Zero real functionality.** Every button (Add, Edit, Delete, New Sale, Export, Sign Out) is broken.
2. **Fake authentication.** Any credentials let you in. All routes are publicly accessible.
3. **All data is hardcoded.** Nothing persists. Every page reload resets to the same fake data.
4. **No backend at all.** This cannot be deployed as a real product without a server.
5. **@tanstack/react-query is set up but never used.** The QueryClientProvider wraps the app but no query hooks exist.
6. **TypeScript strict mode is OFF.** `strict: false`, `strictNullChecks: false`, `noImplicitAny: false` — these settings defeat the purpose of TypeScript.
7. **No real tests.** The only unit test is `expect(true).toBe(true)`.
8. **Data inconsistency.** `RecentSalesTable` and `SalesPage` both define the same sales in separate hardcoded arrays that can diverge. Same with `LowStockAlerts` and `InventoryPage`.
9. **Settings page is an empty shell.** It has 3 decorative cards but no actual functionality.
10. **Unused dead code.** `NavLink` component and `Index.tsx` page are never used.

## 12. BACKEND REVIEW

**There is no backend.** To make this app functional, you need one of:

**Option A — Supabase (Recommended for this project)**
- Fully managed PostgreSQL database
- Built-in REST + realtime APIs
- Built-in authentication (email/password, social)
- Row Level Security (authorization)
- Free tier available
- Perfect for a small business app like this

**Option B — Custom Node.js backend**
- Express or Fastify
- JWT authentication
- PostgreSQL with Prisma ORM
- More control, more work

**Option C — Firebase (alternative)**
- NoSQL (Firestore) — less ideal for this relational data
- Built-in auth
- Free tier

**Recommendation: Supabase.** It integrates perfectly with Vite/React, has an excellent TypeScript SDK, and the relational data model (parts → sales → workers) fits PostgreSQL perfectly.
